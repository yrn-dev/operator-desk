# Плагины оператора

Плагин добавляет агенту инструменты. Это папка с манифестом `plugin.json`,
которую приложение подхватывает при старте диалога.

Плагины бывают двух видов:

| Вид | Что это | Когда выбирать |
| --- | --- | --- |
| `tool` | Ваш код внутри процесса агента | нужен доступ к системе, файлам, своим API — и максимальная скорость |
| `mcp` | Внешний сервер по протоколу MCP | уже есть готовый сервер (их сотни) или код на другом языке |

Разница только в том, где выполняется код. Для агента инструменты обоих видов
выглядят одинаково.

---

## Где лежат

| Папка | Что в ней |
| --- | --- |
| `<настройки>/plugins` | ваши плагины — сюда копирует кнопка «Установить из папки» |
| `<настройки>/plugins-builtin` | встроенные, едут с приложением |
| `<настройки>/plugins.json` | что выключено и с какими настройками |
| `<настройки>/plugins-data` | хранилище самих плагинов |

`<настройки>` — папка данных приложения: `~/.config/operator-desk` в Linux,
`~/Library/Application Support/operator-desk` в macOS,
`%APPDATA%\operator-desk` в Windows. Открыть её можно кнопкой в окне «Плагины».

## Манифест

```json
{
  "id": "notes",
  "name": "Заметки проекта",
  "description": "Решения, которые агент помнит между диалогами.",
  "version": "1.0.0",
  "author": "ProjectZero",
  "kind": "tool",
  "icon": "note",
  "entry": "index.mjs",
  "settings": [
    { "key": "file", "label": "Файл заметок", "default": ".operator-notes.md" }
  ],
  "permissions": ["Читает и пишет файл заметок в рабочей папке"]
}
```

| Поле | Смысл |
| --- | --- |
| `id` | идентификатор, он же имя папки; по нему плагин включается и настраивается |
| `kind` | `tool` или `mcp` |
| `entry` | файл модуля для `tool`, по умолчанию `index.mjs` |
| `command`, `args`, `env` | как запускать сервер для `mcp` |
| `icon` | логотип: файл в папке плагина (`"icon.svg"`, `"logo.png"`) или имя бренда из Simple Icons (`"slack"`, `"notion"`, `"stripe"`) — см. раздел «Логотип» |
| `startupTimeout` | сколько секунд ждать запуска сервера `mcp`; по умолчанию 30, для удалённых со входом через браузер — 300 |
| `settings` | поля, которые пользователь заполняет в окне «Плагины» |
| `permissions` | человеческим языком: к чему плагин получает доступ |

### Логотип

У каждого плагина свой знак. Приложение ищет его по порядку и берёт первое найденное:

1. **Файл автора.** Поле `"icon": "icon.svg"` или просто файл `icon.svg`, `icon.png`,
   `logo.svg`, `logo.png` в папке плагина. Самый надёжный способ — так знак точно
   официальный. Файл не больше 512 КБ; SVG лучше квадратный.
2. **Официальный знак бренда** из набора Simple Icons (3400+ логотипов). Ищется по
   `icon`, `id`, `name` и npm-пакету сервера: `@notionhq/notion-mcp-server` → Notion,
   `mcp-server-kubernetes` → Kubernetes, любой `@modelcontextprotocol/server-*` → знак
   протокола MCP. Можно указать бренд прямо: `"icon": "stripe"`.
3. **Аватар организации на GitHub**, если бренда в наборе нет. Берётся из поля
   `repository` npm-пакета, скачивается один раз и лежит в кеше.
4. Если не нашлось ничего — монограмма с первой буквой названия.

Тёмные знаки (GitHub, Notion) на тёмной теме рисуются цветом текста, остальные —
фирменным цветом.

Поле настроек: `key`, `label`, необязательные `hint`, `default`, `secret`
(поле-пароль), `env` — имя переменной окружения, в которую значение попадёт
при запуске сервера `mcp`, и `arg: true` — если сервер ждёт значение не в окружении,
а последним аргументом командной строки (так устроен, например, адрес базы у
`@modelcontextprotocol/server-postgres`). С `required: true` плагин не
запускается, пока поле пустое, и в списке сразу видно, что нужно заполнить, —
вместо полуминутного ожидания сервера, который без этого значения не заработает.

## Плагин вида `tool`

Модуль экспортирует функцию по умолчанию. Она вызывается один раз при старте
диалога и получает API.

```js
// index.mjs
export default function myPlugin({ operator, settings, storage, log, id }) {
  operator.registerTool({
    name: "weather",
    label: "Погода",
    description: "Показывает погоду в городе. Используй, когда спрашивают про погоду.",
    parameters: {
      type: "object",
      additionalProperties: false,
      required: ["city"],
      properties: {
        city: { type: "string", description: "Название города" },
      },
    },
    async execute(_id, params) {
      const previous = storage.get("last");
      storage.set("last", params.city);
      return {
        content: [{ type: "text", text: `В городе ${params.city} ясно. Прошлый запрос: ${previous ?? "—"}` }],
        details: {},
      };
    },
  });
}
```

Что приходит в аргументе:

| Поле | Что даёт |
| --- | --- |
| `operator.registerTool(tool)` | регистрирует инструмент: `name`, `label`, `description`, `parameters` (JSON Schema), `execute` |
| `operator.on(event, handler)` | события агента, например `tool_call` — можно остановить чужой вызов |
| `settings` | значения полей из манифеста, которые ввёл пользователь |
| `storage` | `get(key, fallback)`, `set(key, value)`, `all()` — файл рядом с настройками |
| `log(text)` | строка в поток ошибок агента; видна с `OPERATOR_DESK_DEBUG=1` |
| `id`, `dir` | идентификатор плагина и путь к его папке |

Результат `execute` — объект с `content: [{ type: "text", text }]`, полем
`isError` при неудаче и `details` для служебных данных.

**Пишите описания для модели, а не для человека.** `description` инструмента —
единственное, по чему агент решает, звать ли его. Хорошо: «Показывает погоду
в городе. Используй, когда спрашивают про погоду или сборы в дорогу». Плохо:
«Погодный инструмент».

## Плагин вида `mcp`

Своего кода нет, только манифест:

```json
{
  "id": "playwright",
  "name": "Playwright",
  "description": "Браузер под управлением агента.",
  "version": "1.0.0",
  "kind": "mcp",
  "icon": "playwright",
  "command": "npx",
  "args": ["-y", "@playwright/mcp@latest"],
  "settings": [
    { "key": "token", "label": "Токен", "secret": true, "env": "SERVICE_TOKEN" }
  ]
}
```

Инструменты сервера появляются у агента под именами `<id>__<инструмент>`.
Значения настроек с полем `env` уходят серверу переменными окружения.

## Как проверить свой плагин

1. Положите папку в `<настройки>/plugins` или нажмите «Установить из папки».
2. Откройте «Плагины» — плагин должен появиться в списке включённым.
3. Начните новый диалог: плагины подключаются при старте, в уже открытый
   диалог они не попадут.
4. В строке плагина видно, сколько инструментов он дал. Если написано
   «не запустился» — там же будет причина.
5. Подробности: запустите приложение с `OPERATOR_DESK_DEBUG=1` и смотрите
   `operator-desk.log` во временной папке.

## Что важно знать

- **Плагин вида `tool` выполняется внутри процесса агента** и может всё, что
  может сам агент: читать файлы, ходить в сеть, запускать программы.
  Ставьте только то, чему доверяете, — как и любое расширение редактора.
- Ошибка в плагине не роняет агента: он попадёт в список со словом
  «не запустился» и причиной, остальные продолжат работать.
- Плагины поднимаются параллельно и не задерживают начало диалога. Внешний
  сервер может подключиться на несколько секунд позже — его инструменты
  появятся, когда он будет готов.
- **Серверы `mcp` ленивые.** После первого запуска список инструментов
  запоминается (`<настройки>/plugins-data/tools`), и в следующих диалогах сервер
  не запускается, пока агент не вызовет его инструмент. После 5 минут без
  вызовов сервер засыпает и освобождает память. Первый вызов после сна
  дольше на время запуска. Поля манифеста: `idleTimeout` — простой в секундах,
  `keepAlive: true` — не усыплять вовсе (если серверу важно не терять
  состояние, например открытые вкладки браузера).
- Встроенные плагины нельзя удалить, но можно выключить.
