# Operator · десктоп

Настольный коммутатор для агента [operator](https://github.com/yrn-dev/operator).
Не эмулятор терминала: приложение поднимает `opr --mode rpc` и говорит с ним
по JSONL, а весь диалог, инструменты и телеметрию рисует само.

Интерфейс минималистичный и бесцветный: фон и текст — фирменные цвета
ProjectZero (`#1C1917` / `#F7F4F0`), активное выделяется яркостью, а не оттенком.
Цвет появляется только там, где несёт смысл: успех, ошибка, внимание.

## Что умеет

- **Один список сессий** — открытые и прошлые вместе, сгруппированные по датам.
  Текущая подсвечена, у открытых стоит точка, у работающей — зелёная.
- **Живая лента**: ответы в markdown с подсветкой кода и копированием блоков,
  сворачиваемый поток размышления, компактные карточки вызовов инструментов.
  Планы задач показываются списком с отметками, а не сырым выводом.
- **Вклинивание**: пока агент работает, отправленное сообщение уходит как `steer`,
  а не ждёт очереди.
- **История по датам** — все прошлые сессии operator из `~/.opr/agent/sessions`,
  сгруппированные по дням; клик открывает ленту целиком (`switch_session`).
  Метка показывает, откуда сессия: `operator-desk` или `operator-cli`.
- **Правый клик по сессии** — переименовать (пишется в файл сессии записью
  `session_info`), сохранить как HTML (через `opr --export`) или JSON, показать
  файл в проводнике, удалить с подтверждением.
- **Слэш-команды** — «/» в поле ввода показывает скиллы, шаблоны и команды
  расширений (`get_commands`); ↑↓ выбирают, Tab подставляет.
- **Название придумывает модель** по первой реплике — отдельным однократным
  запуском `opr --print` — и сохраняется в сессию через `set_session_name`.
- **Вложения** — кнопка «+» в поле ввода или перетаскивание файлов в окно. Картинки уходят модели как изображения
  и показываются миниатюрой; остальные файлы передаются путями — operator читает
  их сам, целиком или нужными частями, без конвертации и без расхода контекста.
- **Расход контекста** в заголовке, предупреждение при заполнении окна.
- **Выбор модели рядом с полем ввода** — список сгруппирован по провайдерам
  (Alem AI: qwen3-8, gemma4, gpt-oss; Ollama и прочие ниже).
- **Ключи доступа** — оттуда же: добавить, заменить или убрать ключ провайдера.
  Значения хранит сам operator в `~/.opr/agent/auth.json`, наружу отдаётся только
  факт наличия ключа и его последние символы.
- **Сжатие контекста и новая сессия** — в меню «…».

### Возможности поверх оператора

Десктоп подгружает в процесс оператора собственное расширение
(`electron/bridge/desk-bridge.mjs`), поэтому следующее работает без правок CLI:

- **Подтверждение опасных команд** — `rm -rf`, `git push --force`, `mkfs` и подобные
  требуют явного разрешения; «разрешить всегда» запоминается правилом. Обычная
  работа идёт без вопросов.
- **Откат правки** — перед каждым `write`/`edit`/`patch` снимается копия файла,
  последнюю правку можно отменить кнопкой под полем ввода.
- **Субагент** — инструмент `subagent` уводит объёмную подзадачу в отдельный
  процесс оператора и возвращает только итог, не тратя контекст диалога.
- **Плагины** — свой код внутри агента или внешний сервер MCP: и то и другое
  даёт агенту новые инструменты. Кнопка «Плагины» в боковой панели, формат
  описан в [PLUGINS.md](PLUGINS.md).
- **Фоновые процессы** — `background_run`, `background_check`, `background_stop`:
  dev-серверы и сборки живут отдельно от диалога, в шапке виден счётчик.
- **GitHub** — инструмент `github` поверх `gh`: создание и просмотр PR, проверки.
- **Хуки** — команды на события `tool_result` и `agent_end` задаются в `policy.json`
  рядом с настройками приложения.
- **Автопилот** — инструмент `computer`: снимок экрана, клики, ввод текста,
  горячие клавиши, запуск приложений. Включается кнопкой у поля ввода, по
  умолчанию выключен. Снимок доставляется модели отдельным сообщением, потому что
  в Chat Completions результат инструмента несёт только текст. Нужна модель со
  зрением (qwen3-8, gemma4) — иначе инструмент честно об этом скажет.

  Снимок экрана делает само приложение (Electron `desktopCapturer`) — одинаково
  во всех системах. Для кликов и ввода нужна системная программа: `xdotool`
  (X11), `ydotool` (Wayland), `cliclick` (macOS); в Windows ввод идёт через
  PowerShell и `user32`.

- **Знание о среде** — `electron/bridge/desk-prompt.md` добавляется к системному
  промпту флагом `--append-system-prompt`: агент знает про свои инструменты,
  подтверждения, откат и про то, что недостающие интеграции подключаются
  MCP-сервером. Основной промпт (`~/.opr/agent/SYSTEM.md`) не затрагивается.

## Требования

Ничего. Ядро operator упаковано внутрь приложения и запускается встроенным
Node — ни Node.js, ни глобальная установка `opr` не нужны. Если в системе уже
есть свой `opr`, используется он.

Нужен только ключ провайдера (вводится в приложении) и, по желанию:

| Для чего | Что поставить |
| --- | --- |
| клики и ввод в автопилоте (Linux Wayland) | `ydotool` + служба `ydotoold` |
| клики и ввод в автопилоте (Linux X11) | `xdotool` |
| клики в автопилоте (macOS) | `cliclick` |
| пул-реквесты | `gh` |
| MCP-серверы | Node.js (для `npx`) |

Окно «Готовность» (меню «…») показывает, что уже работает, чего не хватает и
какой командой это ставится. Снимок экрана делается средствами самого
приложения, внешние программы для него не нужны.

## Разработка

```bash
npm install
npm run dev        # окно с горячей перезагрузкой
npm run typecheck  # проверка типов
npm run smoke          # сквозной тест: поднимает сессию и гоняет реальный запрос
npm run check:restore  # открывает сессию из истории и собирает ленту
npm run check:attach   # отправляет модели картинку вложением
```

## Сборка

Каждая система собирается своей командой; готовые файлы появляются в `release/`.

```bash
npm run dist:linux       # AppImage + deb
npm run dist:linux:rpm   # rpm — нужен rpmbuild (Arch: rpm-tools, Debian: rpm)
npm run dist:linux:pacman  # пакет Arch: sudo pacman -U release/Operator-*.pacman
npm run dist:win         # exe: установщик nsis + portable
npm run dist:mac         # dmg + zip, отдельно для arm64 и x64
```

| Система | Что выкладывать | Чем собирать |
| --- | --- | --- |
| Linux | `.AppImage` (везде), `.deb` (Debian/Ubuntu), `.rpm` (Fedora), `.pacman` (Arch) | любая Linux-машина |
| Windows | `.exe` установщик (nsis), рядом — portable | Windows; с Linux возможно через wine |
| macOS | `.dmg` для arm64 и для x64 | только macOS, кросс-сборки нет |

Названия файлов складываются как `Operator-<версия>-<ос>-<арх>.<расширение>` —
на странице загрузки их можно давать ссылками без переименования.

### Подписи

Без подписи приложение работает, но система предупреждает при первом запуске:

- **Windows** — SmartScreen покажет «Windows защитила ваш компьютер»; запуск
  через «Подробнее → Всё равно выполнить». Убирается сертификатом подписи кода:
  положите его в `CSC_LINK` и `CSC_KEY_PASSWORD`, сборщик подпишет сам.
- **macOS** — Gatekeeper скажет «Программа повреждена»; открывается через правый
  клик → «Открыть». Убирается подписью Developer ID и нотаризацией: переменные
  `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`,
  `APPLE_TEAM_ID`. Права доступа для автопилота уже описаны в
  `build/entitlements.mac.plist`.
- **Linux** — подпись не требуется.

Для сборки на чужой машине есть отдельная инструкция — [BUILD.md](BUILD.md):
её можно отдать вместе с архивом проекта, там пошагово и с разбором ошибок.

### Что проверить на чужой машине

```bash
npm install          # electron и сборщик поставятся под эту систему
npm run typecheck
npm run dev          # окно должно открыться и показать «Чем займёмся?»
npm run dist:win     # или dist:mac — смотря где вы находитесь
```

Диагностика при сбоях — `OPERATOR_DESK_DEBUG=1`: в `$TMPDIR/operator-desk.log`
пишется, каким ядром запущена линия, чем она завершилась и что сказал stderr.

## Переменные окружения

| Переменная              | Смысл                                                |
| ----------------------- | ---------------------------------------------------- |
| `OPERATOR_DESK_PROMPT`  | задание, которое уходит сразу после запуска сессии     |
| `OPERATOR_DESK_ATTACH`  | файлы к этому заданию, через `:`                      |
| `OPERATOR_DESK_DEBUG=1` | диагностика в `$TMPDIR/operator-desk.log`             |

## Как устроено

```
electron/
  main.ts        окно, IPC, протокол app:// для сборки рендерера
  rpc.ts         процесс operator: JSONL по stdin/stdout, корреляция id ↔ ответ
  locate-opr.ts  поиск бинарника operator мимо урезанного PATH
  sessions.ts    чтение истории сессий из ~/.opr/agent/sessions
  preload.ts     мост в рендерер через contextBridge
src/
  lineReducer.ts поток AgentEvent → лента переговоров
  components/    список сессий, заголовок, лента, markdown, поле ввода
```

Рендерер отдаётся по собственному протоколу `app://`, потому что ES-модули
по `file://` блокируются CORS. Preload собирается в CommonJS (`.cjs`) — Electron
не грузит его как ESM.
