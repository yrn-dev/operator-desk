# Сборка Operator Desk на Windows и macOS

Эта инструкция — для того, кто получил проект архивом и должен собрать из него
готовое приложение. Её можно отдать ИИ-агенту целиком: шаги идут по порядку,
у каждого есть признак успеха и разбор частых сбоев.

Linux собирается на машине автора, здесь он не рассматривается.

---

## 0. Что это и что должно получиться

`operator-desk` — настольное приложение (Electron + Vite + React), оболочка для
ИИ-агента `operator`. Ядро агента упаковывается внутрь приложения, поэтому
пользователю готовой сборки не нужен ни Node.js, ни отдельная установка `opr`.

На выходе один-два файла в папке `release/`:

| Система | Файлы | Для чего |
| --- | --- | --- |
| Windows | `Operator-<версия>-win-x64.exe` | установщик (NSIS) |
| Windows | `Operator-<версия>-win-x64-portable.exe` | запуск без установки |
| macOS | `Operator-<версия>-mac-arm64.dmg` | Apple Silicon (M1–M4) |
| macOS | `Operator-<версия>-mac-x64.dmg` | Intel |

Размер каждого файла — 120–160 МБ, это нормально: внутри и Electron, и ядро агента.

---

## 1. Что нужно поставить заранее

**Обязательно — только Node.js 20 LTS или новее** (проверено на 22.x) вместе с npm.

```bash
node --version    # должно быть v20.x или выше
npm --version
```

- **Windows**: установщик с nodejs.org, вариант LTS. Ничего больше не нужно —
  ни Visual Studio, ни Python: нативных модулей в проекте нет.
- **macOS**: `brew install node` либо установщик с nodejs.org. Xcode не нужен,
  Command Line Tools — тоже.

Нужен доступ в интернет: `npm install` тянет Electron (~100 МБ), а отдельный
шаг сборки скачивает пакет `pzero-operator` из npm.

---

## 1.1. Откуда взялся архив (для автора)

Архив собирается на машине автора одной командой — в него попадают только
исходники, без служебных папок:

```bash
npm run zip:source     # создаёт ../operator-desk-source.zip (~0,5 МБ)
```

## 2. Распаковать архив

Разверните архив в путь **без пробелов и кириллицы** — так спокойнее и
сборщику, и путям внутри установщика.

- хорошо: `C:\dev\operator-desk`, `~/dev/operator-desk`
- плохо: `C:\Users\Имя\Рабочий стол\новая папка\operator-desk`

В архиве не должно быть папок `node_modules`, `vendor`, `dist`, `dist-electron`,
`release` — они создаются заново. Если они есть, удалите их перед сборкой:

```bash
# Windows PowerShell
Remove-Item -Recurse -Force node_modules, vendor, dist, dist-electron, release -ErrorAction SilentlyContinue

# macOS
rm -rf node_modules vendor dist dist-electron release
```

---

## 3. Установить зависимости

```bash
npm install
```

Признак успеха: появилась папка `node_modules`, в конце нет строк `npm error`.

Если вывод оборвался на скачивании Electron — повторите команду, загрузка
продолжится с кеша.

---

## 4. Проверить, что системные ветви кода в порядке

```bash
npm run check:platform
npm run typecheck
```

Первая команда проверяет, как приложение запускает внешние программы именно в
этой системе (в Windows это отдельная логика: `npx`, `gh` и `opr` там — обёртки
`.cmd`, которые нельзя выполнить напрямую). Ожидаемый итог — `всё верно`.
Вторая команда молча завершается, если типы в порядке.

Если что-то упало — **остановитесь и сообщите автору вывод целиком**, не
правьте код: скорее всего, дело в самой системе, а не в проекте.

---

## 5. Запустить в режиме разработки

```bash
npm run dev
```

Признак успеха: открылось окно приложения, слева список диалогов, в центре знак
и надпись «Чем займёмся?». Окно закрывается обычным способом, в терминале
`Ctrl+C`.

Что нормально на этом шаге:

- список диалогов пуст — истории на новой машине нет;
- внизу написано «модель» вместо названия модели — ключ провайдера не введён;
- окно «Готовность» сообщает, что чего-то не хватает — это про необязательные
  возможности (автопилот, `gh`), сборке они не мешают.

Что ненормально: окно не открылось, окно белое, окно с ошибкой. В этом случае
перезапустите с диагностикой и приложите лог к сообщению автору:

```bash
# Windows PowerShell
$env:OPERATOR_DESK_DEBUG=1; npm run dev
# лог: %TEMP%\operator-desk.log

# macOS
OPERATOR_DESK_DEBUG=1 npm run dev
# лог: $TMPDIR/operator-desk.log
```

---

## 6. Собрать приложение

### Windows

```bash
npm run dist:win
```

Собирается установщик NSIS и portable-версия. Это занимает 3–10 минут: сначала
в `vendor/` ставится ядро агента, потом пакуется Electron.

### macOS

```bash
npm run dist:mac
```

Собираются `.dmg` и `.zip` **для обеих архитектур** — arm64 и x64. Если нужна
только та, на которой вы сидите, добавьте архитектуру:

```bash
npx electron-builder --mac dmg --arm64      # только Apple Silicon
npx electron-builder --mac dmg --x64        # только Intel
```

Признак успеха в обоих случаях: последняя строка сборщика без значка `⨯`, а в
`release/` лежат файлы из таблицы в разделе 0.

---

## 7. Проверить собранное приложение

Установите или запустите то, что получилось, и убедитесь:

1. приложение открывается (про предупреждения системы — раздел 8);
2. видно окно с надписью «Чем займёмся?»;
3. в меню «…» открывается «Готовность», и первая строка — «Ядро operator» —
   отмечена как рабочая: значит ядро упаковалось внутрь;
4. в поле ввода можно печатать.

Дальше можно не проверять: запрос к модели требует ключ провайдера, вводить
чужой ключ на чужой машине не нужно.

**macOS дополнительно**: при первом запуске система может спросить разрешения
на «Запись экрана» и «Универсальный доступ» — это для автопилота. Для проверки
сборки их можно не давать.

---

## 8. Предупреждения системы при первом запуске

Приложение не подписано сертификатом, поэтому обе системы предупреждают. Это
ожидаемо и не означает поломку.

**Windows.** Синее окно «Windows защитила ваш компьютер» →
«Подробнее» → «Всё равно выполнить».

**macOS.** «Программу нельзя открыть, так как её автор не может быть проверен»
или «программа повреждена». Обходится так: в Finder правый клик по приложению →
«Открыть» → «Открыть» в диалоге. Если не помогает:

```bash
xattr -dr com.apple.quarantine /Applications/Operator.app
```

Чтобы предупреждений не было, нужна подпись — см. раздел 10.

---

## 9. Что делать при типичных ошибках сборки

| Сообщение | Что значит и что делать |
| --- | --- |
| `cannot execute cause=exec format error` | Собираете не под свою систему. `dist:win` запускайте на Windows, `dist:mac` — на macOS. |
| `wine is required` | Попытка собрать Windows-сборку не на Windows. Соберите на Windows. |
| `identity not found` / `No identity found for signing` | Нет сертификата Apple. Отключите поиск подписи: `CSC_IDENTITY_AUTO_DISCOVERY=false npm run dist:mac`. |
| `EPERM: operation not permitted, symlink` (Windows) | Нет прав на символические ссылки. Включите «Режим разработчика» в параметрах Windows либо запустите терминал от администратора. |
| `ENOENT ... rpmbuild` | Это про Linux-цель, вам она не нужна: собирайте только `dist:win` / `dist:mac`. |
| `Error: Cannot find module ... pzero-operator` | Не прошёл шаг упаковки ядра. Проверьте интернет и выполните `node scripts/bundle-operator.mjs` отдельно. |
| Сборка падает на `@electron/rebuild` | Повторите `npm install`, затем сборку: обычно это недокачанный архив Electron. |

Если ошибка не из таблицы — приложите к сообщению автору **последние 40 строк
вывода** и версии: `node --version`, `npm --version`, версию системы.

---

## 10. Подпись (необязательно, нужен сертификат автора)

Без подписи всё работает, но система предупреждает. С сертификатом достаточно
задать переменные окружения — код и конфиг менять не нужно.

**Windows** (сертификат подписи кода, файл `.pfx`):

```bash
$env:CSC_LINK="C:\путь\cert.pfx"; $env:CSC_KEY_PASSWORD="пароль"; npm run dist:win
```

**macOS** (Apple Developer ID, нотаризация):

```bash
export CSC_LINK=~/certs/developer-id.p12
export CSC_KEY_PASSWORD=пароль
export APPLE_ID=почта@apple.id
export APPLE_APP_SPECIFIC_PASSWORD=пароль-приложения
export APPLE_TEAM_ID=XXXXXXXXXX
npm run dist:mac
```

Права доступа, которые запрашивает приложение на macOS (снимок экрана,
управление вводом), уже описаны в `build/entitlements.mac.plist`.

---

## 11. Что вернуть автору

1. Файлы из `release/` — те, что перечислены в разделе 0 (только установщики,
   папку `release/*-unpacked` отправлять не нужно).
2. Строку с версиями: система, `node --version`, `npm --version`.
3. Вывод `npm run check:platform`.
4. Если что-то пошло не так — `operator-desk.log` из временной папки
   (`%TEMP%` в Windows, `$TMPDIR` в macOS) и последние 40 строк вывода сборки.

Папки `node_modules`, `vendor`, `dist`, `dist-electron` обратно отправлять не
нужно.
